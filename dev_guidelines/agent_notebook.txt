# AI Agents need to write in this txt breefly describing their impressions on how they need to work in the project


## Agent Guidelines & Project Operational Rules

1. **Architecture & Runtime (Zero Build Step)**:
   - Pure client-side static web application with Vanilla JavaScript (ES Modules).
   - No bundling tools (no npm build, Vite, or Webpack). All scripts must be directly importable by modern browsers.
   - Test locally with standard HTTP servers (`python3 -m http.server 8000` or `npx serve .`).

2. **Offline-First & Service Worker**:
   - The app must function offline as a PWA.
   - Any added/modified core assets must be reflected in `sw.js` and `CACHE_NAME` version incremented when updating cacheable assets.

3. **Design System & UX Standards**:
   - Strictly follow `dev_guidelines/DESIGN_LANGUAGE.md` (Material Design 3 / Material You Expressive).
   - Use the established tonal palette, smooth elevation shadows, and touch ripple effects. Do not introduce extraneous styling frameworks.
   - Use `#3b82f7` as the designated blue color for icons and buttons across the app's theme.

4. **Game State & Spaced Repetition**:
   - Maintain the logic defined in `dev_guidelines/GAME_ARCHITECTURE_AND_RULES.md` across the study modes (Active Recall, Double Open, Cloze, Multiple Choice, Anki 4-button).

5. **Licensing & DCO Compliance (Linux Model)**:
   - License: `GPL-2.0-only`.
   - Always place the SPDX short-identifier header at the top of new source files (`// SPDX-License-Identifier: GPL-2.0-only`).
   - Retain existing copyright notices; append new author lines when significantly modifying files.
   - Always create commits using the `-s` flag (`git commit -s -m "..."`) so that commits include the required `Signed-off-by:` line.
   - The automated DCO check runs exclusively on incoming Pull Requests.

6. **Strict Theme Rule: Light Mode Only (Prohibited Dark Mode)**:
   - **DO NOT implement, re-introduce, or design for Dark Mode**. The application is strictly Light Mode only.
   - Never add `@media (prefers-color-scheme: dark)`, `.dark` selectors, `dark:` Tailwind classes, or theme toggles.
   - Maintain all backgrounds, containers, typography, and contrast tokens strictly within the Light Theme Material Design 3 specifications.

7. **Internationalization (i18n)**:
   - The internationalization file (`js/i18n.js`) strictly supports only Portuguese (`pt-BR`) and English (`en-US`).
   - Do not introduce or support any other language or locale dictionary.

8. **Image Cropping & Vector Arrow Annotations (No File Saving)**:
   - When modifying or displaying cards with images, keep fetching from web URLs (`card.image`, `card.answerImage`).
   - Store crop and arrows as pure lightweight metadata (`imageCrop`, `imageArrows`, `answerImageCrop`, `answerImageArrows`) to preserve browser storage quotas and Firestore 1MB limits. Never save Base64 data URLs or binary image blobs to card objects.
   - Use `renderAnnotatedImage` from `js/image-editor-modal.js` for rendering images across gameplay, creator, editor, and thumbnails.

9. **Scientific Guide & Educational Article Pattern**:
   - Educational articles explaining learning neuroscience, Bloom's Taxonomy, and algorithm mechanics are integrated into `pages/how-to-write-good-flashcards.html` and linked from `pages/generate.html`.
   - Maintain the journalistic serif style (`Newsreader` font) paired with Material You Expressive tokens, 28px corner radii, and `#3b82f7` theme blue.
   - Do not use Unicode emojis; use Google Fonts Material Symbols exclusively.
   - Provide full bilingual support (`pt-BR` and `en-US`) in `js/i18n.js`.

10. **SEO & Structured Data (Schema.org JSON-LD)**:
   - Public landing and article pages include JSON-LD structured data (`TechArticle`, `FAQPage`, `BreadcrumbList`, `WebApplication`).
   - Canonical URLs and social metadata (Open Graph, Twitter card) must be kept accurate.
   - Maintain root `sitemap.xml` and `robots.txt` referencing `https://flashcards.camblu.org/sitemap.xml`.
